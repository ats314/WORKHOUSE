# AGENT_PROTOCOL — how to run one session

## The loop

1. **Orient (≤5 min).** Read `CHARTER.md` → `STATE.md` (top) → `GUARDRAILS.md`. Stop there — you now understand the project. Reading further "to get up to speed" is the trap.
2. **Scope.** Confirm the one unit of work with Alex (a milestone in a `programs/` campaign, or a deliverable step). If none is given, propose one from `STATE`'s next-actions and wait for sign-off.
3. **Do the unit.** Read deeply only what that unit needs. Hard-gate every numeric claim (assert, don't warn).
4. **Record.** Update `STATE.md` (status first) and `records/SESSION_LOG.md` (one short entry). Deposit any citable result into the right layer (`theory`/`programs`/`numerics`/`papers`) — not only into a finding file.
5. **Stop.** Don't roll into a second unit unprompted.

## Claim tiers — label every status-bearing claim

- **T1 · machine-gated** — a hard-asserting gate reproduces it from the working home. Necessary, not sufficient.
- **T2 · internally-reviewed** — a *different* agent/session checked the argument line-by-line.
- **T3 · externally-validated** — a human or outside tool/referee confirmed it.

Status in `STATE` advances only when the matching tier is met. **A T1 pass is not a theorem. Only T3 counts as "established" for any outward claim.**

## Definition of done (for a deliverable)

Written so a domain referee could accept it; assumptions/conditions stated honestly; every constant routed through `theory/DOC_GOV_conventions.md`; every load-bearing computation reproducible from `C:\THEORY`. Then: out to an external reader. That last step is the point — not another hardening pass.
